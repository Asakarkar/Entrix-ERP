# Vercel and Render deployment

The frontend is a Vite single-page app for Vercel. The Express API is deployed separately on Render. MongoDB must be reachable over the internet; a local MongoDB instance cannot be used by Render.

## 1. Prepare MongoDB

Create a MongoDB database (for example, on MongoDB Atlas) and allow connections from the Render service. Use its connection string for the Render `DATABASE` variable. Keep database credentials out of the repository.

## 2. Deploy the API to Render

Create a Render Blueprint from the repository root using `render.yaml`. The service runs from `backend/`; Render supplies the port. Configure the prompted variables:

- `DATABASE`: the MongoDB connection string.
- `CORS_ORIGINS`: comma-separated, exact Vercel origin(s), without a trailing slash (for example, `https://your-app.vercel.app`). Add a custom domain here too if you use one.
- `OWNER_EMAIL` and `OWNER_PASSWORD`: credentials for a new database. Use a password of at least 12 characters.
- `JWT_SECRET` is generated by the Blueprint.

After the API is deployed, copy its `https://...onrender.com` URL. For a new, empty database, open the Render Shell in `backend/` and run `npm run setup` once. Do not run setup on every deploy or against a database that already has an owner; it is intended only for initial provisioning.

`RESEND_API` is optional, but is needed for password-reset emails. `PUBLIC_SERVER_FILE` can be set to the API's public URL for PDF links.

The Blueprint uses Render's free web-service plan to avoid creating a paid service automatically. Free services can spin down while idle; choose a paid plan in Render if the API must remain always on.

## 3. Deploy the frontend to Vercel

Import the same repository into Vercel and set **Root Directory** to `frontend`. Vercel uses `frontend/vercel.json` for client-side route fallback. Set these Production environment variables:

- `VITE_BACKEND_SERVER`: the Render API URL, with or without a trailing slash.
- `VITE_FILE_BASE_URL`: the same Render API URL unless files are served from a separate host.

Deploy the frontend, then add its exact production origin to Render's `CORS_ORIGINS` and redeploy the API. If Vercel assigns a different production domain, update the allowlist accordingly.

## Storage note

Uploaded profile photos and logos currently use the backend's local filesystem. Render's filesystem is ephemeral, so these uploads can disappear after a restart or redeploy. This setup leaves uploads ephemeral as requested; use persistent storage before relying on uploaded files in production.

## Repository note

The project currently has no Git metadata. Vercel and Render Git-based deployments require the project to be initialized and pushed to a Git provider first.
